# Open issues

- darkroom never checks `ImageHandle::is_resident`. After the window host recovers from a lost GPU device, every image darkroom registered paints nothing: the canvas dot tile (`darkroom/src/gui/pane/graph_ui/canvas_bg.rs`), the viewer checker tile (`darkroom/src/gui/pane/image_viewer/mod.rs`, `draw_checker`) and every preview thumbnail and full texture in `darkroom/src/gui/state/preview_store`, which keeps no texels or source to upload again once a full texture is resident. A full texture also keeps the size `Ui::max_image_dimension` capped it to on the lost device.
- The graph canvas pans by an exact `TranslateScale`, so a pan off the physical pixel grid at zoom 1, as a zoom to the pointer that returns to 1 leaves, paints nodes, wires and text on fractional pixels.
- The worker report channel (`darkroom/src/core/worker_bridge/mod.rs`, `WorkerBridge::new`) is an unbounded `std::sync::mpsc::channel` that only `App::update` drains. A minimized or occluded window runs no frame, and the worker keeps running, so a graph with a live event loop (a Frame Event, a busy Watch Directory) queues Activity reports and run summaries for as long as the window stays hidden. Headless MCP grows the same way between tool calls.
- The preview converter thread (`darkroom/src/gui/state/preview_store/preview_converter.rs`, `PreviewConverter::new`) is detached, and `PreviewConverter::ready` reads its results with `try_iter`, which yields nothing once the thread is gone. A panic in a conversion under the unwinding `mcp` profile ends the thread, and no preview converts again, with no report.
