# Open issues

- **lumos `memory_budget` fails intermittently.** `tests/memory_budget/live_heap.rs` counts every thread's allocations, and the test harness's own threads allocate between tests — a finished test's thread exiting, the main thread recording its result — while the next test, holding `HEAP.exclusive()`, measures. The `detection::*_holds_the_same_heap_for_any_frame_count` tests fail in about one run of five at a load average of 5–15, a different detector from run to run, each by a few hundred bytes (111000 against 112161 B for the default detector).
- **`.zed/tasks.json` names a profile no root defines.** "run darkroom release-max with tracy" and "run palantir showcase with tracy" pass `--profile release-max`, which neither the darkroom nor the palantir `Cargo.toml` declares, so both tasks fail.
- **Two lens func ids are hand-typed, not generated.** In `lens/src/image/nodes/processing.rs`, `BRIGHTNESS_CONTRAST_FUNC_ID` (`b8c3d4e5-f6a7-4b8c-9d0e-1f2a3b4c5d6e`) and `TRANSFORM_FUNC_ID` (`d3e4f5a6-b7c8-4d9e-0f1a-2b3c4d5e6f7a`) are runs of sequential hex digits rather than `uuidgen` output, and they ship in saved graphs.
- **lumos FITS writers flatten `fits_well::FitsError` into `io::Error`.** `CfaFitsHdu::encode`, `FlagsExtension::encode`, `GainExtension::encode`, `io::fits::cfa::save` and `CalibrationMasters::save` report `io::Result`, converting every fits-well failure through `io::fits::to_io` into `ErrorKind::InvalidData`; the bundle writer also builds `io::Error`s from messages (`invalid_data` in `calibration/calibration_masters/fits.rs`) for a defect index or extent past the FITS signed-64 range.
- **`CalibrationMasters::build` takes five parameters.** `frames`, `sigma_threshold`, `ingest`, `cache` and `monitor`, a public entry point called from `lens` and the lumos examples, tests and benches.
- **lumos cosmic-ray detection allocates its masks per plane.** `MonoDetector::reject_with` builds a fresh `CrMasks` (three frame-sized bit masks) on every call, and `BayerDetector::reject` a fresh `plane_found` mask and a sampled `KeptOut` (two more) for each of the four phases, so every frame a pass cleans allocates them anew; `BitBuffer2` has no way to be reshaped for the next plane.
