# Palantir swallowed-logic audit

Audited production Rust under `palantir/src` and `palantir/anim-derive/src` for optional branches and similar control flow that turn a reachable logic failure into apparently valid output. The scan covered `if let Some`, let-else early exits, `.ok()`, `unwrap_or*`, ignored `Result`s, `filter_map`, truncating `zip`, and sparse cursor advancement. Intentional optional paths such as cache misses, empty paint, dropped image handles, unavailable window positions, clipboard degradation, and event-loop shutdown are not listed.

Re-verified on 2026-07-28 by independently tracing every call path and running focused temporary regression probes where the existing test harness could exercise the failure. All five findings remain confirmed; the probes were removed after the run.

## Findings

1. **Confirmed — reproduced.** `palantir/src/scene/tree/paint_anims/mod.rs:261-274` — `PaintAnimCursor::sample` advances past every registered animation below the requested shape index, but does not re-check whether the next registered index is now *above* the requested index. With animations at shapes 2 and 10, a direct cursor probe at shape 6 returned shape 10's sampled animation instead of `PaintMod::IDENTITY`; shape 10 then received no animation. `emit_one_shape` samples only emitted shapes (`palantir/src/renderer/frontend/encoder/mod.rs:308`), while viewport and damage culling skip whole ranges, making the between-indices jump reachable. The existing sparse-cursor test jumps exactly onto the final registered shape and misses this overshoot case.

2. **Confirmed — source-proven; deterministic reproduction requires an allocation-failure seam.** `palantir/src/renderer/backend/text/encode.rs:304-306` — when `rasterize_and_insert` returns `None` specifically because the atlas is at the device maximum and has no currently evictable rectangle, the glyph is skipped with `continue`. The `culled` flag only records lines removed by geometric y-culling, so it stays false and the shortened glyph span is inserted into the encoded-run cache at `palantir/src/renderer/backend/text/encode.rs:344-352` as if it were complete. Subsequent cache hits replay the truncated span without retrying rasterization. If the run stays hot and none of its recorded slots is invalidated, the missing glyph can persist indefinitely even after competing atlas pressure disappears. `rasterize_and_insert` can also return `None` when the font rasterizer produces no image; that permanent non-image case is not the defect described here.

3. **Confirmed — reproduced through scoped chord routing.** `palantir/src/input/scope.rs:81-91` — `Scopes::resolve` excludes `closing` and `closed` rows when deriving `active_layer` and the focused path, but `outermost_of` scans the unfiltered stale cascade at `palantir/src/input/scope.rs:179-186`. With sibling popup scopes A then B, closing B left the next Escape fallback grant assigned to stale B; `ui.escape_pressed()` inside surviving A returned false. The raw keyboard buffer still contains the event and layer silencing still works, but the surviving scope cannot receive the scoped chord. The existing two-scope test closes first-recorded A and checks only raw layer blocking, so it cannot expose this ordering error.

4. **Confirmed — reproduced at the state transition and traced through pointer capture.** `palantir/src/widgets/scroll/state.rs:153-159` — `apply_thumb_drag` clears `drag_anchor` when the pointer drag ends, but a focused probe showed that it remains set when geometry becomes absent. Geometry legitimately becomes `None` when content starts fitting or the track collapses; the zero-extent thumb remains recorded, capture eviction sees its ID still present, and drag deltas remain cumulative from the original press. If usable geometry returns while that same on-surface capture is still held, the stale anchor resumes against the full accumulated delta and makes the offset and thumb jump. Releasing or leaving before geometry returns clears the anchor and does not trigger the bug.

5. **Confirmed — reproduced with a nonempty option list.** `palantir/src/widgets/combo_box/mod.rs:90` — with `options = ["One"]` and `selected = 3`, the ComboBox completed normally, recorded no label shape, and left `selected == 3`. The public API documents a trigger showing the current choice and exposes no no-selection or placeholder state, so `options.get(...).unwrap_or("")` masks an invalid caller-owned model value as a normal blank control. Shrinking or replacing the option list can reach this state between frames. Current in-tree callers maintain valid indices; this is a public API contract failure rather than a presently broken Palantir caller.
