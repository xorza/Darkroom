# Scenarium swallowed-logic audit

Audited production Rust under `scenarium/src` for optional branches, fallback values, ignored results, lossy conversions, inferred absence, and related control flow that turns a reachable logic failure into apparently valid state or loses the original failure. The audit covered `if let Some`, let-else exits, `.ok()`, `unwrap_or*`, ignored `Result`s, `filter_map`, truncating `zip`, graph-boundary resolution, cache reconciliation, resource fingerprints, and state downcasts. Intentional paths such as absent bindings, library-drift ports, cache misses, best-effort cache writes, dropped reply receivers, disabled nodes themselves, and event-loop shutdown are not listed.

Verified on 2026-07-28 by tracing each retained call path and running focused temporary regression probes where the existing harness could exercise the failure. The probes were removed afterward, and the untouched crate passed all 315 unit tests plus doc-tests. All fourteen findings below remain confirmed.

## Findings

1. **Confirmed — cold path reproduced; warm path source-proven.** `scenarium/src/execution/plan/mod.rs:52-60,208-211`, `scenarium/src/execution/resolve/mod.rs:178-182`, and `scenarium/src/execution/executor/value_flow.rs:57-60` — an optional input bound to an unseeded disabled producer is considered satisfied, so its consumer enters the schedule while the producer does not. Resolution nevertheless marks the absent producer live and records a read, and input collection unconditionally expects its output to be resident. Executing the existing plan-only regression produced the `a resolved producer output must be resident when consumed` panic on a cold cache. With a retained RAM value from before the producer was disabled, the same unchecked read can instead deliver stale pre-disable output.

2. **Confirmed — output side reproduced; input-side mirror source-proven.** `scenarium/src/execution/flatten/mod.rs:425-475` — the type-drift gate is applied to a composite interface declaration, but the subsequent boundary traversal follows the interior or exterior binding through raw `resolve_binding`. A definition declaring an `Int` output but binding it to a `String` producer compiled a direct `Bind` into an `Int` consumer instead of degrading to unbound. `GraphInput` has the mirrored defect: the boundary resolves as `Any`, so an incompatible outer value can pass into a typed interior consumer.

3. **Confirmed — reproduced.** `scenarium/src/execution/compile/mod.rs:178-191` — `run_targets` infers which interior nodes back a composite's outputs from flattened consumer topology, but flattening has already removed the `GraphOutput` edges. In a focused nested fixture with a real exposed producer, an interior-only reader, and a dead interior terminal, `run_targets(instance)` selected the dead terminal and omitted the exposed producer. A run-to-instance request can therefore demand the wrong output cone.

4. **Confirmed — reproduced.** `scenarium/src/execution/resource/mod.rs:75-97` — a directory stamp includes only each immediate entry's name, length, and mtime; it does not descend into subdirectories. Changing `root/sub/file` from three bytes to six left the fingerprint of `root` unchanged on the test filesystem. A pure function that recursively consumes a directory can consequently reuse output produced from old nested contents.

5. **Confirmed — collision reproduced; filesystem reachability source-proven on Unix.** `scenarium/src/execution/resource/mod.rs:89` — `DirEntry::file_name().to_string_lossy()` collapses distinct non-UTF-8 byte names to the same replacement-character string. Focused fingerprints built from Unix names containing `0xff` and `0xfe` were identical when metadata matched. Filesystems that admit arbitrary Unix byte names can therefore rename an entry without changing the directory cache identity.

6. **Confirmed — reproduced.** `scenarium/src/execution/resource/mod.rs:28-33` — a valid mtime before the Unix epoch makes `duration_since` fail, and `.ok().unwrap_or(0)` maps every such time to zero. Two same-length files stamped one and two seconds before the epoch produced identical resource fingerprints, so distinct pre-1970 versions can share a pure node's cache key.

7. **Confirmed — reproduced in debug builds.** `scenarium/src/execution/cache/runtime/mod.rs:133-153,353-360` and `scenarium/src/execution/validate.rs:233-239` — cache reconciliation retains a resident RAM snapshot when the same function changes output arity. Because its old digest still matches its old `produced_under`, `release_dead_outputs` also retains it; install's debug validator then panics on the stale snapshot length. Adapting the existing evolved-function test from a grown input to a grown output reproduced `installed compiled graph invariant violated: OutputArity`. Release builds restamp and recompute on the next run, so this is a debug/development install failure.

8. **Confirmed — reproduced through caught unwind.** `scenarium/src/graph/boundary/mod.rs:342-349` — `restore_bindings` inserts the detached binding before checking whether the port already held wiring authored after detachment. The promised refusal panics only after overwriting the newer binding. Catching the panic in the existing overlap test showed the new `Const(99)` wire had been replaced by the detached wire, leaving the graph mutated and potentially partially restored.

9. **Confirmed — reproduced through caught unwind.** `scenarium/src/library.rs:165-181` — `register_type` inserts a new enum entry before validating defaults on functions that were registered first. When validation rejects an enum whose variants omit an existing default, the panic leaves the rejected `TypeEntry` installed. The existing test observes only the panic; a focused postcondition check found `library.types` still contained the invalid registration.

10. **Confirmed — reproduced in the supported function-first order; the reverse order follows the same branch.** `scenarium/src/library.rs:165-217` and `scenarium/src/graph/validate.rs:325-329` — `enum_variants(id) == None` means both “type not registered yet” and “type registered as custom.” The supported deferred-registration path therefore accepts a function declaring `DataType::Enum(id)` followed by `TypeEntry::custom(id)` without error. The same ambiguous `None` later makes its accepted enum constant fail `const_satisfies` and silently flatten as unbound.

11. **Confirmed — reproduced.** `scenarium/src/runtime/any_state.rs:54-84` — `AnyState::get_or_default` and `get_or_default_with` treat a failed downcast exactly like an empty state slot. Setting a `String` and then requesting the default `u32` silently replaced and dropped the string. Runtime slots are already tied to a function/version owner, so a populated wrong type is an implementation invariant violation that these helpers erase.

12. **Confirmed — reproduced.** `scenarium/src/execution/disk_store/mod.rs:44-47,112-160` — decoding a header-valid but corrupt cache body relies on deleting the blob to make the next run recompute, but `BlobTarget::delete` ignores every removal error. With the parent directory made non-writable, the decode failed, deletion failed silently, the blob survived, and its header continued to pass `covers_demand`. The resolver will prune the producer cone and report `CacheLoadFailed` again on every run while the file remains undeletable.

13. **Confirmed — reproduced with Tokio's paused clock.** `scenarium/src/elements/worker_events_library/mod.rs:122-128` — every execution of the Frame Event source resets `last_fps_emit`, even though the FPS event callback owns that timestamp when it emits. At 2 Hz, re-executing the source 250 ms after initialization postponed the already-waiting FPS event from 500 ms to 750 ms. An immediate `Always` subscriber that reads the source outputs can repeatedly re-execute it and indefinitely postpone the simultaneous FPS event.

14. **Confirmed — reproduced.** `scenarium/src/data/static_value.rs:57-62` — float-to-bool coercion uses `abs() > f64::EPSILON`, although the type-system contract says any nonzero scalar reads as true. `StaticValue::Float(f64::MIN_POSITIVE).as_bool()` returned `Some(false)`, silently collapsing a real nonzero value to false.

## Checked and excluded

- Clone remapping's identity fallback, missing-port/event exits in flattening, wildcard `Any` resolution, and sparse boundary snapshots are deliberate library-drift or unbound-state behavior.
- Cache probe/read `None` paths and most disk-store write failures are documented cache misses or best-effort persistence; the undeletable corrupt-body case is listed because forward progress specifically depends on the ignored deletion.
- Worker sync replies, pause-gate notifications, event-channel closure, empty-graph runs, and context logging outside invocation are intentional no-ops.
- Cache-slot and validator `zip` calls are fed by paired construction paths in production; focused tracing found no reachable silent truncation apart from the separately listed output-arity transition.
- Per-entry directory I/O failures also degrade stamps, but were not retained as separate findings because no deterministic injection seam exists and the confirmed fingerprint collisions above establish the cache-identity failures without relying on races.
