# Darkroom

The node-graph editor: a native desktop app on palantir, and a driver that runs it with no
desktop for an agent or a test.

## What is here

- `src/core/` — the document, its edits and undo, file I/O, the runtime host and the worker.
- `src/gui/` — the app, the main window, the panes (graph, image viewer, inspector,
  preferences), the theme and darkroom's own widgets.
- `src/driver/` — the editor harness: plays input, waits for the editor to settle, reads back
  state as text and the window as pixels, offscreen or in the desktop window.
- `src/platform/` — each OS behind one API.
- `../app/` (`darkroom-app`) — the `darkroom` binary: the command line, the window or headless
  start, and the MCP server.
- `assets/ayu-graphite.ron` — the palette, generated by `~/Projects/ayu-graphite`
  (`make darkroom`, then copy). Never edit it by hand.
- `sample/` — the sample project. Change it in the editor, never by a script: a test opens it
  and runs it to its previews.

## Guidance

- **See the editor through MCP.** `darkroom_open` with `copy: true` unless you mean to edit the
  file, then `darkroom_state` and `darkroom_ui` for text, `darkroom_shot` when the look matters,
  `darkroom_act` for a batch of input, `darkroom_wait_run` for a run.
- **Never sleep or count frames.** Each action waits until the editor settles; work off the frame
  reports through `App::is_busy` and wakes the window through `Ui::waker`.
- **Sizes come from the theme's scales** — text, space, radius, stroke, icon. A literal at a call
  site is a missing token.
- **One formatter per kind of value** — `ShownValue`, `Percent`, `format::node_name`, the byte
  sizes — shared by the canvas and the inspector.
- **A tint over a known ground is `color::wash`**; `with_alpha` only over content the code does
  not know. A surface that floats over content wears `theme::frosted`.
- **A widget id reads `darkroom.<area>.<name>`.**
- **A palette change goes through ayu-graphite**, so every target keeps one source.

## Decisions

### The editor harness

- **Flags on one binary.** `darkroom [FILE]` is the window, `--mcp` adds the server on stdio
  beside it, `--mcp --headless` has no window. Refused: a subcommand, and a separate server
  binary that drifts ([Playwright MCP](https://github.com/microsoft/playwright-mcp)).
- **One driver, two backends**, palantir's players: offscreen in `Harness` on a stepped clock, or
  the desktop window through `Remote` between two frames. Refused: a request queue in the app.
- **The harness drives the real `App`**, with its runtime, worker and previews. Refused: a
  fixture library, which cannot open a real project.
- **MCP over stdio, nothing else on stdout**; `.mcp.json` starts the binary `cargo drive run mcp`
  builds. Refused: a loopback HTTP server, and `cargo run`, whose build outlasts the client's
  timeout ([MCP transports](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)).
- **The process is the session.** An open replaces the project, a quit or a panic ends the
  server; a window outlives its server. Refused: sessions inside one server.
- **A project opens in place**, as a person's Open does; `copy` opens a copy in a temp folder.
  Refused: a copy by default, whose saves a person watching would have to find.
- **A dialog takes a queued answer, else asks the person**, and headless refuses. Refused: every
  dialog scripted under `--mcp`, which cancels the person's own.
- **A screenshot is product API**: `darkroom_shot` asks through `Ui::request_screenshot`, as View ▸
  Copy View as Image does. Refused: a test-only readback.
- **No CPU display in the product**: headless needs a GPU adapter, and a software one counts.
  Refused: a silent fallback, which passes tests that never ran.

### The document

- **The document file** is RON text in `.darkroom`, or that text zipped in `.darkroomz`, as
  Inkscape writes `.svg` and `.svgz`; a load reads the form the bytes show.
- **Paths in a document** are absolute in memory and relative inside the document's folder in
  the file, never with `..`. Refused: relative paths in memory, which an undo after Save As would
  point at another file
  ([Blender](https://docs.blender.org/manual/en/latest/files/blend/open_save.html)).

### Undo

- **The camera is outside the undo history.** Pan and zoom are saved but never undone, as
  Photoshop keeps them out of History.
- **A held gesture is one entry, and Esc takes it back whole**, a preview spawn and its drag
  alike. Refused: Blender's Shift+D, where Esc leaves the copy.

### Wire ties

A tie gathers wires into a ribbon. It is view data in `GraphView`: saved and undoable, ignored
by compile, plan and run. Refused: a pass-through node, which changes the graph for layout.

- **A route is stored, a strand's slot is derived**, each frame by the barycenter heuristic
  (Sugiyama, Tagawa, Toda 1981), as strands cross after nodes move.
- **The tie line is Shift+RMB-drag**, Ctrl+Shift+LMB on a trackpad: the breaker's chord plus
  Shift, as Blender adds reroutes. Refused: hold Z, as palantir has no key release.
- **The line only ties**; Delete or the tie's menu removes a tie. Refused: a line that toggles.
- **A wire is both of its ends**: a route is keyed by `WireKey`, so a rewire drops it in the same
  undo step. Refused: a key by the input alone.
- **A tie is an item** in the one selection, beside nodes. Refused: a second selection set.
- **A node set takes the ties inside it**, for a drag and a duplicate alike.
- **One wire leaves through the tie's menu**. Refused: dragging a strand out of the band.
- **The band is neutral and paints over wires, under nodes**, so the wire colors stay the types.

### The look

- **A status and a type share a hue, never a form**: a status is a frame, a footer word and the
  status bar; a type is a port dot and a wire, as Blender and Unreal draw a red Bool beside a red
  error.
- **The accent is palantir's dark lime**, so the editor and its widgets wear one; the info status
  keeps Ayu's blue, which the Path wire shares.
- **A good run is quiet, and one cause gets one red frame**: a node a failure skipped says so in
  its footer. Refused: a glow per good run, and a frame per skipped node.
- **Undo reads "Undo"**, as commands reach the history as batches of intents. Refused: a step
  name read off them, which misnames a compound command.
- **One dialog button order on every platform**, right-aligned with the confirming one last.
  Refused: Qt's order by platform, which needs platform code in palantir.
