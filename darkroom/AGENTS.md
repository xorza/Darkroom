# Darkroom

The node-graph editor: a native desktop app on palantir, and a driver that runs it with no
desktop for an agent or a test.

## What is here

- `src/core/` — the document, its edits and undo, file I/O, the runtime host and the worker.
- `src/gui/` — the app, its window and panes, the theme and darkroom's own widgets.
- `src/driver/` — the editor harness: plays input, waits for the editor to settle, reads back
  state as text and the window as pixels.
- `src/platform/` — each OS behind one API.
- `../app/` (`darkroom-app`) — the `darkroom` binary and its MCP server.
- `assets/ayu-graphite.ron` — the palette, generated by `~/Projects/ayu-graphite`
  (`make darkroom`, then copy). Never edit it by hand: a palette change goes through
  ayu-graphite, so every target keeps one source.
- `sample/` and `src/gui/app/session/bench.darkroom` — documents tests open. Change them in the
  editor, never by a script.

## Guidance

- **See the editor through MCP.** `darkroom_open` with `copy: true` unless you mean to edit the
  file, then `darkroom_state` and `darkroom_ui` for text, `darkroom_shot` when the look matters,
  `darkroom_act` for a batch of input, `darkroom_wait_run` for a run.
- **A second pass is the last resort**: settle the state before it records, or in the pass that
  reads it. A relayout, a second record pass or another frame stays only where it is the
  idiomatic answer, with a comment at the site.
- **Never sleep or count frames.** Each action waits until the editor settles; work off the frame
  reports through `App::is_busy` and wake the window through `Ui::waker`.
- **Sizes come from the theme's scales**; a literal at a call site is a missing token.
- **One formatter per kind of value**, shared by the canvas and the inspector.
- **A tint over a known ground is `color::wash`**; `with_alpha` only over content the code does
  not know. A popup over content wears `theme::GLASS`; a toolbar pill has no blur.
- **A widget id reads `darkroom.<area>.<name>`.**

## Decisions

### The editor harness

- **Flags on one binary**: `darkroom [FILE]` is the window, `--mcp` adds the server on stdio,
  `--mcp --headless` has no window. Refused: a subcommand, and a separate server binary that
  drifts ([Playwright MCP](https://github.com/microsoft/playwright-mcp)).
- **One driver, two backends**, palantir's players: offscreen in `Harness` on a stepped clock, or
  the desktop window through `Remote`. Refused: a request queue in the app.
- **The harness drives the real `App`**, with its runtime, worker and previews. Refused: a
  fixture library, which cannot open a real project.
- **MCP over stdio, nothing else on stdout**; `.mcp.json` starts the binary `cargo mcp` builds.
  Refused: a loopback HTTP server, and `cargo run`, whose build outlasts the client's timeout
  ([MCP transports](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)).
- **The process is the session**: an open replaces the project, a quit or a panic ends the
  server. Refused: sessions inside one server.
- **A project opens in place**, as a person's Open does; `copy` opens a copy in a temp folder.
  Refused: a copy by default, whose saves a person watching would have to find.
- **A driven session leaves the preferences file alone**: it starts on the defaults and keeps its
  changes in memory, so a test neither reads the person's settings nor writes them. Refused:
  reading the file, which makes two runs of one test differ by machine.
- **A dialog takes a queued answer, else asks the person**, and headless refuses. Refused: every
  dialog scripted under `--mcp`, which cancels the person's own.
- **A screenshot is product API**, the request View ▸ Copy View as Image makes. Refused: a
  test-only readback.
- **A lost device is replaced offscreen too**, through the call the start made, so an agent sees
  the editor recover. Refused: a session that ends with its device.
- **No CPU display in the product**: headless needs a GPU adapter, a software one included.
  Refused: a silent fallback, which passes tests that never ran.

### The document

- **The document file** is RON text in `.darkroom`, or that text zipped in `.darkroomz`, as
  Inkscape writes `.svg` and `.svgz`; a load reads the form the bytes show.
- **Paths are absolute in memory and relative inside the document's folder in the file**, never
  with `..`. Refused: relative paths in memory, which an undo after Save As would point at
  another file ([Blender](https://docs.blender.org/manual/en/latest/files/blend/open_save.html)).
- **A path in another system's absolute form stays as the file holds it**; the load report names
  it and the node that reads it fails. Refused: refusing the load, which makes a project
  unopenable for one outside path; clearing the input, which a Save then loses.

### Undo

- **The camera is outside the undo history**, as Photoshop keeps pan and zoom out of History.
- **A held gesture is one entry, and Esc takes it back whole.** Refused: Blender's Shift+D, where
  Esc leaves the copy.

### Wire ties

A tie gathers wires into a ribbon: view data, saved and undoable, ignored by compile, plan and
run. Refused: a pass-through node, which changes the graph for layout.

- **A route is stored, a strand's slot is derived** each frame by the barycenter heuristic
  (Sugiyama, Tagawa, Toda 1981), as strands cross after nodes move.
- **The tie line is Shift+RMB-drag**, Ctrl+Shift+LMB on a trackpad, the breaker's chord plus
  Shift, as Blender adds reroutes; it only ties, and Delete or the tie's menu removes one.
- **A wire is both of its ends**, so a rewire drops its route in the same undo step.
- **A tie is an item** in the one selection, and a node set takes the ties inside it. Refused: a
  second selection set.
- **One wire leaves through the tie's menu.** Refused: dragging a strand out of the band.
- **The band is neutral and paints over wires, under nodes**, so the wire colors stay the types.

### Input

- **One scroll rule on every OS**: a scroll pans, the command key with a scroll zooms about the
  pointer, and a pinch zooms, as
  [Figma](https://help.figma.com/hc/en-us/articles/360041065034-Adjust-your-zoom-and-view-options)
  does; Windows and X11 report a touchpad in lines, so a rule by unit leaves a touchpad no way to
  pan. Cost: a plain wheel does not zoom. Refused: a setting for it, as
  [Godot](https://docs.godotengine.org/en/4.3/classes/class_graphedit.html) offers; reading the
  device through platform code, as
  [Blender](https://lists.blender.org/pipermail/bf-blender-cvs/2022-May/173122.html) does.

### The look

- **A status and a type share a hue, never a form**: a status is a frame, a footer word and the
  status bar; a type is a port dot and a wire, as Blender and Unreal draw a red Bool beside a red
  error.
- **The accent is palantir's dark lime**; the info status keeps Ayu's blue, which the Path wire
  shares.
- **A good run is quiet, and one cause gets one red frame**: a node a failure skipped says so in
  its footer.
- **Undo reads "Undo"**, as commands reach the history as batches of intents. Refused: a step name
  read off them, which misnames a compound command.
- **A dialog's buttons sit right-aligned**, the confirming one last. Refused: Qt's order by
  platform, which needs platform code in palantir.
